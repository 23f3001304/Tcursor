# src/hud/Hud.tsx

Root component of the floating recorder bar. Owns device selection, export flags, and the active panel directly; delegates the record/stop/preprocess lifecycle to `useRecordingFlow`. Wires together every visual region: the titlebar, device dropdowns, mic meter, timer, and the animated overlay panels for Settings and Preferences. This is the single stateful hub; all child components are controlled.

## Hud

Renders the full HUD window content and manages the recording lifecycle.

### Props

- `onEdit?: (folder: string) => Promise<void>` - optional callback invoked after `stopRecording` succeeds, with the project folder path. *Why:* the stop path no longer automatically kicks off the export pipeline; instead it hands the folder to the caller (`App`) so it can open the editor. When `onEdit` is not provided the recorder operates in standalone mode and the export is not triggered. NOT called by a graceful close (`handleClose`) - see below. *Why a `Promise` (fix round 1, item 2, controller ruling 2026-09-02):* `useRecordingFlow`'s `finish` awaits it (via `handOff`, `docs/api/src/hud/hooks/useRecordingFlow.md`) before deciding whether to reset `saving` - `App.tsx`'s `openEditor` (the real `onEdit`) does its own async window resize before switching views, and `finish` must not let its own saving-reset `setSize` race that.

### Behavior

**Window constant.** `WIDTH = 980`, the fixed horizontal size of the IDLE bar window, is imported from `src/hud/hooks/useHudWindowSize.ts` (single source of truth, since that hook is also the one calling `win.setSize` with it) - `openPanel`/`restoreBar` (below) always morph back out to this width, never `RECORDING_WIDTH` (the buttons that open a panel are hidden while recording, so the two never need to interact). The box dimensions (BOX_W=360, BOX_H=440) are local constants used by both the open and restore transitions.

**State and hooks.**
- `displays / mics / sel / setSel` - enumerated devices and current selection from `useDevices`, which polls `listDisplays` and `listAudioInputs` via IPC on mount AND re-polls on every `devicechange` (task-6 (d)). *Why a hook:* keeps enumeration and refresh logic out of this file.
- `camId` - selected camera device id, or `null` to mean "first available". *Why nullable:* the browser does not guarantee a stable device id across sessions.
- `camOn` - whether the camera preview and recording are active. *Why separate from camId:* lets the user keep a camera selected but temporarily disabled without losing the selection.
- `camStreamRef` - a ref holding `cam.stream` (below), threaded into `useRecordingFlow` as `camStream: () => camStreamRef.current()`. *Why a ref instead of passing `cam.stream` directly:* `cam`'s own `enabled` argument (below) needs `saving`, which only exists once `useRecordingFlow` has already returned - declaring `cam` before `useRecordingFlow` (the old order) would make `saving` unavailable, but declaring `useRecordingFlow` first needs `cam.stream` before `cam` exists. The ref breaks that circularity: `useRecordingFlow` gets a stable wrapper function up front, and `cam`'s own declaration (right after) points `camStreamRef.current` at the real getter - by the time anything actually CALLS it (`webcam.start`, at record-start), it's already live.
- `recording / paused / saving / savePct / err / toggle / togglePause / stopForClose` - from `useRecordingFlow` (see `docs/api/src/hud/hooks/useRecordingFlow.md`), which owns the whole record -> stop -> preprocess -> edit lifecycle. `stopForClose` is the graceful stop `handleClose` (below) runs before the window actually closes. `exporting`/`pct` (below) stay local to `Hud` - they are unrelated leftover state from before export moved into the editor's `ExportDialog` (see `src/editor/Editor.tsx`); nothing in the current app flow sets `exporting` true from the HUD.
- `cam` - live preview handle from `useWebcamPreview(camId, camOn && !saving)`. Exposes `cam.ref` (bound to the `<video>` element), `cam.on` (whether a stream is active - now also flips back to `false` on a live track ending, and self-recovers on `devicechange` once the device reappears, task-6 (b)/M4), and `cam.stream()` (the `MediaStream` for the recorder). The `&& !saving` (item 4, user-reported 2026-09-02) releases the stream - and turns the camera LED off - the instant Stop's finalize begins, the same as if the user had toggled the camera off; it re-acquires automatically once `saving` goes back to `false`, since that's the same `enabled` gate `useWebcamPreview` already re-runs on. `saving`'s promisified `onEdit` handoff (fix round 1, item 2, see `useRecordingFlow.md`'s `handOff`) means this re-acquire never actually fires on the normal Stop-into-editor path any more, either: `saving` now stays `true` the whole time `Hud` is still mounted after a successful Stop (it only resets on a FAILED handoff, or when there's no `onEdit` at all), so `camOn && !saving` never flips back to `true` before `Hud` unmounts - the brief camera-preview flicker that fix used to cause during the handoff window is gone.
- `cameras` - list of detected camera devices from `useCameraDevices`. Re-enumerates when `cam.on` flips (the numeric argument forces a re-query tick). *Why on `cam.on`:* browsers only expose camera labels after permission is granted, which happens the moment the preview starts.
- `exporting` / `pct` - export progress percentage, driven by `export-progress` Tauri events.
- `exportErr` - the last `export-error` payload, or `null`. Rendered in the same titlebar slot as `err` (task-6 (f)/M3 - an export failure used to be completely silent once the user was back on the HUD; only a best-effort `revealItemInDir` guess ran, which silently no-op'd for any project opened via Open Project). Cleared on the next `export-progress` or `export-done`.
- `panel` - which overlay panel is mounted: `"settings"`, `"preferences"`, or `null`. Drives the `AnimatePresence` overlay.
- `barShown` - toggles the `.as-box` CSS class and gates the bar content subtree. *Why needed:* the window morphs to a smaller box for panels; while morphing the bar must be invisible so it does not flash underneath the incoming panel.
- `lastFolder` ref - stores the project folder path returned by `stopRecording` so the export-error listener can call `revealItemInDir` even after recording state has reset.
- `themeRef` ref - persists `{ theme, accent }` so the `matchMedia` OS-change handler can call `applyTheme` with fresh values without closing over stale state.
- `animatedBrand` (Task 39) - the `ui.animated_brand` feel knob, as real React state (unlike `theme`/`accent`, which apply imperatively via CSS vars through `applyTheme` and so only need a ref) since it's a value `TcursorMark`'s `state` prop is derived from - a prop change needs a re-render. Set from `getSettings()` on mount and from `Preferences`'s `onUiChange` (below).
- `elapsed` - elapsed recording time from `useRecordingTimer(recording, paused)`.
- `mic` - `{ levels, active }` from `useMicWaveform(recording && !paused && micOn)` (see `docs/api/src/hud/hooks/useMicWaveform.md`). *Why `micOn` is folded into the hook's `on` argument, not just its rendering:* this is what stops the mic from being opened at all while the user has it toggled off (task-6 (c), user-reported finding H2 - the HUD used to open the mic and show a live-looking waveform even when muted). Passed straight into `RecMeter`.

**Window sizing (`useHudWindowSize(menu, barShown, saving ? "saving" : recording ? "recording" : "idle")`).**
Extracted hook (`src/hud/hooks/useHudWindowSize.ts`, see its own doc) that resizes the OS window to fit the bar's current content - taller while a dropdown is open so the menu list overflows into extra window space rather than being clipped by the frame, content-fit narrow (`RECORDING_WIDTH`/`SAVING_WIDTH`) while recording or saving (D5 / item 3, user-reported 2026-09-02 - the window used to stay at the idle 980px width around the much narrower recording pill, and separately fell BACK to that same 980px width around ~300px of saving-bar content since `mode` never distinguished "saving" from "idle" before) - and fixes the cold-launch centering bug (L1): the window boots at `tauri.conf.json`'s 860px width, and the hook's first resize to the real 980px bar would otherwise leave it 60px right of screen centre, since `setSize` keeps the top-left corner fixed. `WIDTH` (`980`, imported from this hook module) is also what `openPanel`/`restoreBar` (below) animate the window back out to.

**Theme effect (`useEffect` on `[]`, runs once).**
Calls `getSettings()` and immediately applies the persisted theme and accent color via `applyTheme`, and (Task 39) sets `animatedBrand` from `s.ui.animated_brand`. Attaches a `matchMedia("prefers-color-scheme: dark")` listener so System mode stays reactive to OS changes during the session. Reads from `themeRef` (not state) to avoid a stale-closure bug. Cleans up the listener on unmount.

**`handleClose()` (task-6 (a) / ruling R6).** `await stopForClose(); win.close();` - awaits the graceful stop (a no-op that resolves immediately if nothing is recording, so this is still a single click in the common case) before actually closing the window, so a recording in progress is finalized and saved instead of the process just dying mid-take (the Critical finding this task starts from). This is the React-side half of the fix; `src-tauri/src/lib.rs`'s `on_window_event` `CloseRequested` guard is the Rust-side backstop that holds even if this function never runs at all (OS close button, Alt+F4, a wedged renderer).

**Export event listeners (`useEffect` on `[]`).**
Subscribes to three Tauri events:
- `export-progress` (payload `number`) - updates `pct` and clears `exportErr` (a new progress tick means an export is actively running now, so any stale prior failure message is no longer current).
- `export-done` (payload: the exported file's own absolute path, `<folder>/final.<ext>` - see `run.rs`, not just the project folder) - sets `exporting` false and calls `revealItemInDir` on it directly (no hardcoded `\final.mp4` guess, which used to be wrong for a webm/gif export).
- `export-error` (payload: the error message) - sets `exporting` false, sets `exportErr` to the message (task-6 (f) - THIS is now what surfaces the failure), and best-effort reveals `video.mp4` from `lastFolder` on top of it (still a no-op when `lastFolder` is `""`, i.e. a project opened via Open Project - but the message renders regardless).

All three `listen` promises return unsubscribe functions called on cleanup.

**`toggle()` / `togglePause()` / `stopForClose()`.**
All three come straight from `useRecordingFlow(...)`, fed `micOn`/`sel.micId`/`sel.displayId`/`sysOn`/`gameMode`/`camOn`/`() => camStreamRef.current()` (see `camStreamRef` above)/`webcam`/`onEdit`/`lastFolder`. See `docs/api/src/hud/hooks/useRecordingFlow.md` for the full record -> stop -> preprocess -> edit sequence, the record-button re-entrancy guard, and the graceful-close variant. `lastFolder` itself stays a `Hud`-owned ref (passed into the hook by reference) purely so the unrelated export-error listener above can still read it.

**`openExistingProject()`.**
Calls `openProject()` (native `*.tcursor` file picker) and, on success, `await`s `onEdit?.(folder)` with the returned containing folder - the same prop `toggle()`'s stop path uses, so opening an existing project routes to the editor identically to finishing a fresh recording. Awaited (not fire-and-forget) now that `onEdit` is promisified (fix round 1, item 2) so a rejection lands in the same `catch` as a cancelled dialog rather than becoming an unhandled promise rejection - there is nothing to surface either way.

**Panel transition helpers.**
- `openPanel(p)` - sets `barShown = false`, sets `panel = p`, and calls `morphWindow` to animate the window from bar dimensions to box dimensions over 200ms.
- `restoreBar()` - called from `AnimatePresence`'s `onExitComplete` after the panel exit animation finishes. Calls `morphWindow` back from box to bar dimensions, then sets `barShown = true` so the bar fades in only after the resize completes.

**Rendered regions.**
- `AnimatePresence` overlay: mounts either `<Settings>` or `<Preferences>` with a scale+opacity spring (0.97->1 in, 0.98->0 out over 180ms). `key={panel}` ensures the exit animation fires when switching panels. `<Preferences>`'s `onUiChange` (Task 39 - see `Preferences.md`) updates `themeRef`/`applyTheme` (as before) AND `animatedBrand`.
- Titlebar: drag region with the brand mark + name (`.brand`, `TcursorMark state={animatedBrand && recording ? "recording" : "idle"}` inside `.brand-mark` - see `docs/api/src/lib/TcursorMark.md`), an optional error label (`err ?? exportErr`), and window controls. Open Project, Preferences, and Settings buttons are all hidden while recording or exporting, and all three are additionally `disabled` while `saving` (task-6 (g) - Preferences/Settings used to stay clickable during Saving…, inconsistent with Open Project and able to morph the window mid-save). The Close button (`onClick={handleClose}`) is NOT hidden or disabled during recording/saving - it stays live on purpose, since intercepting the click gracefully (see `handleClose` above) is the fix, not blocking it.
- Grip: left drag handle (`data-tauri-drag-region`).
- Camera preview: `<CamTile>` (`src/hud/components/CamTile.tsx`, see its own doc), rendered `{!saving && <CamTile .../>}` - HIDDEN entirely while saving (item 4, user-reported 2026-09-02: the tile, and the live stream behind it, used to keep showing in the saving bar), shown unchanged in both the idle and recording bar otherwise, since this markup sits above the row's `exporting`/`saving`/`!recording` conditional. `CamTile` itself still covers "toggled off" AND "no camera / device lost" with the same off-glyph (task-6 (i)) whenever it IS rendered.
- Four conditional rows for bar content, in priority order: exporting progress (`exporting`), saving/preprocessing progress (`saving` - a `Saving… {savePct}%` pill, same `.exporting` style class plus a `.saving` hook), device selectors (idle) - the camera `Dropdown` and mic `Dropdown` both run their `label` through `cleanDeviceLabel` (`src/hud/devices/selectDevices.ts`) to strip Windows/cpal's device-name packaging, e.g. `"Microphone (3- Insta360 Link 2C)"` -> `"Insta360 Link 2C"` - `<RecMeter>` (recording - see `docs/api/src/hud/components/RecMeter.md`, redesigned as a compact fixed-width level meter for item 2, user-reported 2026-09-02). The idle device selectors render inside a `.pickers` wrapper (the three pickers separate from each other by spacing, not a divider - D5) and the four cam/mic/sys/game toggles render inside a `.toggle-group` wrapper (one segmented raised group instead of four floating buttons - D5); both are purely presentational groupings in `hud.css`, no new props. The four toggle buttons are `motion.button`s carrying the module-level `TOGGLE_PRESS` spring (design/premium-pass D6, `whileTap: { scale: 0.96 }`, stiffness 500/damping 30) - the one gap left after Record (its own spring, D5) and Pause/Resume (`hud.css`'s `.btn:not(.rec):active` CSS scale) already had press feedback.
- `<RecordingControls>` (`src/hud/components/RecordingControls.tsx`, see its own doc): timer (dims via `.timer.paused` while paused), an animated "Paused" chip (Motion, opacity-pulses; task-6 (h)), Pause/Resume button, and the Record/Stop/Saving hero button, always on the right. The hero button's label reads `Saving…` (no percent - the pill above already shows it) while `saving` is true.

### Notes

- `MotionConfig reducedMotion="user"` wraps the entire tree; all Motion animations (including the paused chip's pulse) disable automatically when the OS has reduced-motion enabled.
- The Preferences and Settings buttons are conditionally rendered (not just disabled) during recording and exporting to avoid occupying titlebar space when those actions are not available; they switch to `disabled` (still rendered) specifically for the `saving` window, matching Open Project.

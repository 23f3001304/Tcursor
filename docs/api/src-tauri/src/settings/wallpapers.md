# src-tauri/src/settings/wallpapers.rs

The curated background library: the bundled wallpaper images plus twelve gradient presets. Both tables are the single source of truth - the export renders from them (`export::scene::background::build`), the editor's picker thumbnails them (`export::preview::bg_thumbs`), and nothing keeps a second copy in TypeScript.

`WALLPAPERS` is GENERATED: `build.rs` scans `assets/backgrounds/wallpapers/*.jpg` and writes the table into `$OUT_DIR/wallpapers_gen.rs`, which this file `include!`s. *Why generated rather than hand-listed:* the sets grow (Ribbons, Folds, Gradients, Metal, Scenic, with more coming) and land one at a time, and a hand-written table is one more place to forget an id or mistype a name. Dropping a JPEG into the folder is the entire change.

The images are embedded with `include_bytes!` (the same treatment `bg.jpg` already gets in `export::render`), so a wallpaper needs no install-time file layout, no user data directory, and no network. They are part of this repository under its MIT license; see `assets/backgrounds/wallpapers/README.md` for their provenance.

## Wallpaper

```rust
pub struct Wallpaper { pub id: &'static str, pub name: &'static str, pub group: &'static str, pub bytes: &'static [u8] }
```

One bundled wallpaper image. Every field is derived from the filename by `build.rs` - see `src-tauri/build.rs` for the rules.

- `id` - the stable identifier stored in `BackgroundSettings.mesh`; the file stem.
- `name` - the label the editor's tile shows: the stem minus its group prefix, hyphens turned into spaces, title-cased (`folds-silk-blue` -> `Silk Blue`).
- `group` - the picker section, from the prefix: `folds-` -> `"Folds"`, `gradient-` -> `"Gradients"`, `metal-` -> `"Metal"`, `scenic-` -> `"Scenic"`, anything unprefixed -> `"Ribbons"`.
- `bytes` - the embedded JPEG (1536x864, q90).

## GradientWallpaper

```rust
pub struct GradientWallpaper {
    pub id: &'static str, pub name: &'static str,
    pub from: [u8; 3], pub mid: Option<[u8; 3]>, pub to: [u8; 3], pub angle_deg: f32,
}
```

One gradient preset: two stops, or three when `mid` is set. Rendered by `export::scene::background::render` (`Background::Gradient`), never by CSS, so the picker tile and the export agree exactly.

## WALLPAPERS

```rust
pub static WALLPAPERS: &[Wallpaper]
```

Every bundled wallpaper, in the order the picker shows them: `Ribbons`, `Folds`, `Gradients`, `Metal`, `Scenic`, alphabetical by display name inside each. A group with no files yet contributes nothing. Generated by `build.rs`; the editor renders the table as-is, one section per group, so this ORDER is the UI.

The legacy `bg.jpg` ("Classic") is deliberately NOT in this table: the empty id means "the legacy mesh", so it is reached by the `None` arm of `wallpaper_by_id` rather than by a library entry. That keeps every pre-library project rendering byte-identically without a special case in the table, and the editor puts its tile first in the grid.

### Behaviors

- `the_generated_table_is_populated_with_unique_ids` - the scan found the assets and every id is unique; a duplicate would make `BackgroundSettings.mesh` ambiguous. Deliberately NOT an exact count - the set grows by dropping files in.
- `every_wallpaper_embeds_a_real_jpeg_a_name_and_a_known_group` - each entry starts with the JPEG SOI marker, is over 10 KB, lands in one of the three known groups, and has a capitalized, hyphen-free name.
- `the_table_is_grouped_in_picker_order_and_alphabetical_inside_each_group` - the emitted order really is Ribbons, Folds, Gradients, Metal, Scenic with each group sorted, since `read_dir` order is arbitrary and only the build script's sort makes it stable.
- `the_naming_rules_survived_the_build_script` - restates the prefix -> group map and checks every shipped file against it (the prefix picks the group, the name is the stem minus that prefix), so changing one side has to be a deliberate change to both. Unprefixed files form `Ribbons`.
- `no_two_wallpapers_are_the_same_image` - guards against a copy/paste that points two ids at one file.

## GRADIENT_WALLPAPERS

```rust
pub const GRADIENT_WALLPAPERS: &[GradientWallpaper]
```

The twelve gradient presets: `indigo`, `tile`, `dusk`, `ember`, `harbor`, `moss`, `grape`, `slate`, `coral`, `fog`, `blush`, `carbon`. Five are three-stop; angles are spread across the circle rather than all sitting at the CSS-default 135 degrees.

### Behaviors

- `gradient_angles_are_varied` - at least eight distinct angles, at least one three-stop preset, and every angle inside `0..360`.

## wallpaper_by_id

```rust
pub fn wallpaper_by_id(id: &str) -> Option<&'static Wallpaper>
```

Look up a wallpaper by the id stored in `BackgroundSettings.mesh`. `None` for the empty id (the legacy mesh) and for any id this build does not have - a project saved by a newer build, or a hand-edited `edit.json`. Both cases route `background::build` to the legacy `bg.jpg`, so the background is never missing.

### Used by

- `src-tauri/src/export/scene/background.rs` (`build`) - resolves `BackgroundSettings.mesh` to the image bytes it decodes.
- `src-tauri/src/export/preview/bg_thumbs.rs` (`background_thumbs`) - iterates both tables to render the editor's picker tiles.

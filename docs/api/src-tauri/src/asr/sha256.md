# src-tauri/src/asr/sha256.rs

FIPS 180-4 SHA-256, hand-rolled. About a hundred lines of pure arithmetic with no `unsafe` and no dependency, pinned against the three standard NIST vectors.

*Why not a crate:* the only thing in this repository that needs a cryptographic hash is the model store, and it needs exactly one algorithm with exactly one call shape (hash a file, compare to a constant). `sha2 = "0.10"` would pull in `digest`, `block-buffer`, `crypto-common`, `generic-array` and `typenum` to do that. The algorithm is fully specified, has not changed since 2001, and is verifiable against published vectors, so the maintenance cost of owning it is a test file. This is the plan's ADDED-6 decision; if the trade is ever re-made the other way, this file deletes and the three call sites keep their signatures unchanged.

*What it is NOT for:* passwords, signatures, or anything an attacker chooses the input to. It checks that a file arrived intact from a known URL.

## Sha256

```rust
pub struct Sha256 { /* private: h, buf, buf_len, total */ }
```

A streaming hasher. `new()` starts it, `update(&[u8])` feeds it any number of chunks of any size, and `finish_hex()` pads and renders the digest. The internal 64-byte block buffer means a caller can hand it 97 bytes at a time or 1 MiB at a time and get the same answer, which is what lets `sha256_file` stream a 465 MiB model without holding it in memory.

`Default` is implemented as `new()` so the type satisfies the usual Clippy lint; it carries no other meaning.

## new

```rust
pub fn new() -> Self
```

A hasher over the empty message: the eight `H0` words (the fractional parts of the square roots of the first eight primes), an empty block buffer, and a zero length.

## update

```rust
pub fn update(&mut self, bytes: &[u8])
```

Absorb `bytes`. Fills the pending partial block first, then compresses whole 64-byte blocks straight out of the caller's slice, then keeps the remainder. Cheap to call in a tight read loop; no allocation.

## finish_hex

```rust
pub fn finish_hex(self) -> String
```

Append the `0x80` byte, the zero padding, and the 64-bit big-endian bit length, then render the eight state words as 64 lowercase hex characters.

Takes `self` BY VALUE on purpose. Padding destroys the state: a hasher used after being finished would produce a silently wrong digest. Consuming it makes that a compile error instead.

The padding length is `56 - ((buf_len + 1) mod 64)`, wrapped to `120 - ...` when the `0x80` byte pushes past the 56-byte mark - the case where the length field needs a whole extra block. `sha256_tests.rs` pins 55, 56 and 64 byte messages precisely because those are the three branches.

## compress

```rust
fn compress(&mut self, block: &[u8; 64])
```

One round of the compression function: the 16-word message schedule expanded to 64 with `s0`/`s1`, then 64 rounds of the `a..h` working variables, then the feed-forward add into the state. Private; the shape is the specification's, and every add wraps.

## sha256_hex

```rust
pub fn sha256_hex(bytes: &[u8]) -> String
```

The digest of a byte slice as 64 lowercase hex characters. The one-shot form of `Sha256`.

### Behaviors

- `matches_the_standard_vectors` - the empty string, `"abc"`, and the 56-byte two-block NIST message. These three are the whole reason a hand-rolled hash is defensible: a wrong implementation cannot pass them by accident.
- `streaming_in_chunks_equals_hashing_in_one_go` - 5000 bytes fed 97 at a time equals the one-shot digest, which exercises the partial-block path on a chunk size that divides neither 64 nor the total.
- `a_message_that_straddles_the_length_padding_boundary_is_correct` - 55, 56 and 64 bytes, the three padding branches.

## sha256_file

```rust
pub fn sha256_file(path: &Path) -> std::io::Result<String>
```

The digest of a file, streamed in 1 MiB reads so a 465 MiB model never lands in memory at once. Propagates the open and read errors rather than turning them into a wrong digest.

### Behaviors

- `hashing_a_file_agrees_with_hashing_its_bytes` - a 3 MiB file, so the read loop runs several times and an off-by-one in the buffer handling cannot hide.

### Used by

- `src-tauri/src/asr/download.rs` (`verify_or_remove`) - the only caller; it hashes a finished `.part` before renaming it onto the model path.
